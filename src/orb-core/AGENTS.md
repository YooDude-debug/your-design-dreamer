# ORB Core rules

- ORB concepts are separate orb_nodes (type fact, metadata.kind=concept, norm_key prefix `concept:`) created only inside the existing background analysis call and validated by src/orb-core/analysis/concepts.ts (verbatim user-text evidence, typed relations with evidence_status, never "confirmed"); concept rows are excluded from memory recall; why: organic graph growth without fixed taxonomy, extra model calls, or memory pollution.
- ORB decision traceability: new ORB snapshots carry `build_id` (build-time content hash via Vite define `__ORB_BUILD_ID__`, else `not_available`), `scope_check` (declared/requested/checked/result) and for autonomous questions `decision_trace` (gate flags, thresholds, top-3 candidate IDs+scores; never contents/prompts) built in src/orb-core/decision-trace.ts; ORB selection queries and sorts end with an `id` tie-breaker before limits; why: actions must map to the running build and ties must not reorder results.
- ORB long-form replies are enabled only by the deterministic `isLongFormRequest` in src/orb-core/long-form.ts (short rule stays default); cut-off replies are kept and flagged via `state_snapshot.completion` (incomplete|continuing|complete), and continuation runs only via `continueOrbReply` on user click, claimed atomically (incomplete→continuing) before exactly one model call; why: no silent truncation, no unnoticed double generation, no extra model call for detection.
- ORB topics/interests are stored only via `semanticTopicOf` (else null); `topicOf` is recall-only; autonomous gaps rank by conversation tier before score, skip name memories, and must pass `checkQuestionFidelity`; why: the user name became the dominant topic.
- ORB short replies ("Ja", "Nein", "Alle 3") to the newest ORB question are bound to it via `pendingOrbQuestion`/`isShortReply` (src/orb-core/conversation.ts) → DIRECT_ANSWER + `replyBindingHint`; autonomous impulses wait while the newest message is an unanswered ORB question, and `repeated_topic` observations need the topic in the current conversation and are locked per topic within the existing question lock; why: "Ja" produced "Ich höre zu" and an unrelated topic interrupted the dialog.
- Knowledge Globe activation pulses come only from validated `orb.retrieval` events (reply recall via buildRetrievalEvent, asked autonomous question via buildQuestionActivationEvent = its source memory) sent as user+scope tab signals; the engine shows them one after another from a bounded queue inside its render loop (no own timers) and never animates edges, because the runtime path reports no traversed connections; why: the red pulse must show only proven activations.
- ORB conversation continuity (P7) lives in src/orb-core/continuity-rules.ts: an always-on prompt rule (current statements beat older memories, no re-asking answered content, statements without a question allowed, clarify unclear references, speculation as scenarios), recalled memories created inside the current context window are tagged "gerade in diesem Gespräch gesagt", short replies to an ORB message with several questions are not bound to one, and autonomous questions are dropped (gate `answered`) when a user message in the window already shares their content stems; why: ORB re-asked answered preferences and presented fresh statements as old memories.
- ORB Synaptic Lab (P8, src/orb-core/synaptic-lab/simulation.ts + /orb/synaptic-lab, admin-only) is a pure deterministic in-browser simulation over a read-only getOrbKnowledgeGraph snapshot (IDs, groups, edges only); it has no write path, no persistence, no events/signals and never auto-confirms hypotheses; why: experiment must never touch productive ORB cognition or data.
- Synaptic Lab long-term test (P9, src/orb-core/synaptic-lab/longterm.ts) reuses stepModel with one seed-derived build/rest/recall plan shared by A/B/C; removed candidates are never restored or re-grown by recall; why: one simulation mechanic, no fabricated reactivation.
- Synaptic Lab model D (P11) reuses stepModel: instead of removal, candidates become `dormant` (metadata kept, restorable by targeted recall from the same key, restore never counted as reactivation) and `expired` after `dormantRetention` steps (never restorable); why: compare reversible pruning without a second mechanic or silent deletion.
- Synaptic Lab adaptive retention (P12, src/orb-core/synaptic-lab/adaptive.ts) runs only on a built-in synthetic graph and reuses stepModel with model-D mechanics; models E/F only set per-connection dormant retention via the optional StepOptions.retention hook (clamped to min/max), reuse is counted from usage-phase events only, never from planned recall; why: compare retention policies without a second mechanic or touching real ORB data.
- Synaptic Lab importance protection (P13, src/orb-core/synaptic-lab/protection.ts) reuses planAdaptive/runAdaptiveModel via optional profile and retention hooks; G = max(F-score, importance), H = F retention + capped bonus above IMPORTANT_THRESHOLD, both clamped to [min,max]; budget comparison lowers only G/H max retention to fit F's dormant×steps; why: one mechanic, D/E/F unchanged, advantages must not come from extra storage.
- ORB memory lifecycle rules (lifecycleFor, weaken, LIFECYCLE_ORDER, analysisLifecycleUpdate) live only in src/orb-core/memory-lifecycle.ts as a pure, scope-free module without DB imports; validate.ts re-exports lifecycleFor, apply.server.ts keeps all writes via the scoped client; why: P14 S1 isolates lifecycle rules for testing before any new lifecycle behavior.
- ORB passive memory evaluation (P14 S2) lives in src/orb-core/memory-evaluation.ts (pure) + memory-evaluation.server.ts (log-only [orb.obs.memory_eval], IDs/numbers/status, never content); called once after the turn summary log, return unused, usage defaults to unknown and is at most usage_candidate on a unique verbatim token absent from user input; why: observe relevance/importance/usage separately without touching retrieval, lifecycle or persistence.
- ORB shadow evaluation (P14 S3) lives only in src/orb-core/memory-shadow.ts: pure comparison of the existing selection (model-visible ids, rank by retrieval relevance) against an alternative score from S2 values, gated by ORB_SHADOW_EVAL_ENABLED=false, never imported by engine/retrieval, invalid inputs stay unknown, foreign scopes dropped; why: observe alternatives without any path back into ORB decisions.
