## Architecture rules

- Cognitive Globe geometry derives from the compact observation and measured existing Memory bounds; camera framing follows visible layer bounds, so presentation cannot alter ORB or Memory semantics. Zoom limits: min distance from the Memory core only, max from visible layers; manual zoom survives layer/cognitive updates (ratio kept on resize) so Memory nodes stay reachable.
- Knowledge Globe reads exactly one validated scope (required, no default) filtered by session user_id + scope, ordered with id last before limits, edges/thread members only to loaded nodes; its query key and BroadcastChannel signals are bound to user id + scope and the query cache is cleared on sign-out/account switch; why: no cross-scope mixing, no stale data of a previous account, deterministic subsets.
- Server-function DB/RPC errors are thrown via internalError() and masked to "Interner Serverfehler" by the global safeServerFnErrors function middleware in src/start.ts; the framework serializes server-fn errors (incl. cause) before request middleware sees them.
- ORB scope isolation: every ORB data access goes through `createOrbCore({ data, userId, scope })`, which wraps the client in `scopedDb` (src/orb-core/scope.ts) so all orb_messages/nodes/connections/threads/questions/interests/candidates queries filter and inserts set `scope` in the query itself; why: one central guarantee instead of ~20 hand-written filters.
- ORB scope comes only from the route `/channels/orb/$scope` (normal | orb_core | y_dude) and is re-validated by Zod in every ORB server function without default; feed observation uses `unassigned`, ORB-Dev is fixed `orb_core`, orb_state/orb_style stay user-wide; why: fixed decision, no text-based scope detection.
- ORB concepts are separate orb_nodes (type fact, metadata.kind=concept, norm_key prefix `concept:`) created only inside the existing background analysis call and validated by src/orb-core/analysis/concepts.ts (verbatim user-text evidence, typed relations with evidence_status, never "confirmed"); concept rows are excluded from memory recall; why: organic graph growth without fixed taxonomy, extra model calls, or memory pollution.
- Autonomous ORB questions (askProactively without explicit) run in every chat scope (AUTONOMOUS_QUESTION_SCOPES = ORB_CHAT_SCOPES; unassigned and unscoped calls stay silent), with data bound to session user + scope via scopedDb, and never twice for the same source memory within QUESTION_MEMORY_LOCK_MS (checked by memory id, not wording, in deriveKnowledgeGaps and decideImpulse); why: ORB is the conversational core of every chat, while wording-based dedupe let one gap repeat endlessly.
- ORB decision traceability: new ORB snapshots carry `build_id` (build-time content hash via Vite define `__ORB_BUILD_ID__`, else `not_available`), `scope_check` (declared/requested/checked/result) and for autonomous questions `decision_trace` (gate flags, thresholds, top-3 candidate IDs+scores; never contents/prompts) built in src/orb-core/decision-trace.ts; ORB selection queries and sorts end with an `id` tie-breaker before limits; why: actions must map to the running build and ties must not reorder results.
- ORB chat message length uses one shared constant (ORB_MESSAGE_MAX_CHARS in src/lib/orb-attachments.ts) in composer, Zod, engine and bridge, rejected never silently truncated; why: four diverging limits cut text silently.
- ORB images (P2) come only from a `[[ORB_VISUAL {...}]]` marker in the normal reply, stripped in the engine before storage, validated + HMAC-signed via the SDK (user+scope+10 min), generated by a separate server fn with a rolling 24h limit counted in orb_visual_generations (no DELETE grant, prompt only as hash); why: no extra decision model call, no images in memory, and limits users cannot reset.
- ORB Visual Memory: images are assets in orb_visual_assets (path `<user>/orb/<scope>/<sha256>.<ext>` in private `media`, DB-trigger-checked) linked to memories only via orb_memory_images (manual or analysis `image_links` whose verbatim quote is in the image's own message); both tables are in ORB_SCOPED_TABLES; why: explicit references only, no time-proximity linking, no cross-scope mixing.
- ORB long-form replies are enabled only by the deterministic `isLongFormRequest` in src/orb-core/long-form.ts (short rule stays default); cut-off replies are kept and flagged via `state_snapshot.completion` (incomplete|continuing|complete), and continuation runs only via `continueOrbReply` on user click, claimed atomically (incomplete→continuing) before exactly one model call; why: no silent truncation, no unnoticed double generation, no extra model call for detection.
- ORB topics/interests are stored only via `semanticTopicOf` (else null); `topicOf` is recall-only; autonomous gaps rank by conversation tier before score, skip name memories, and must pass `checkQuestionFidelity`; why: the user name became the dominant topic.
